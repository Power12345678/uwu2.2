# uwu iOS 消息与短期上下文修复

范围仅为 uwu 网页，不改 Bot。保留现有音乐保活；不假定 iOS 保证后台网页一直执行。已暂停的网页需要云端 Web Push 才能保证继续生成通知，目前不部署未配置的云服务。

1. 为同一聊天的前台/主动消息共用请求锁。进入聊天不能解除请求锁；每个请求持有自己的 AbortController。API 重试只包含网络和响应解析，UI/保存失败不能再次收费请求。
2. 回复解析先收集消息，不等待每个气泡的展示延迟。先把目标聊天和影子上下文一次事务提交，再呈现气泡。上下文重复的相同短句按消息身份处理，不按内容删掉新轮次；已发送未回复的用户消息也保存。保存失败明确提示，恢复前台可补写内存中的未完成保存。
3. toast 带聊天目标，点击与键盘操作都能打开私聊/群聊。系统通知携带相同目标，Service Worker 只聚焦本项目的窗口；冷启动 URL 在数据初始化后处理。隐藏页面即便原聊天仍为 active 也应该通知。只有助手可见消息才通知。
4. 魔法屋增加消息提醒方式（默认静音；可选原有提示音、支持时震动），不播放模拟震动音。iOS 16.4+ 要添加到主屏幕并授权通知。保活状态可诊断，但不承诺保活绕过系统挂起。

验证：Node VM 运行真实业务函数，复现后台目标保存、重复短句、保存失败、请求互斥、通知路由、SSE 尾帧和 iOS Load failed。临时浏览器数据测试真实 IndexedDB 事务；禁止使用用户数据和模型 API。检查现有同步测试回归，更新 README/MEMORY_BANK，提交推送。
